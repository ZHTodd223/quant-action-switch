# Gate-v4 三种子复现实验审计与下一阶段路线

日期：2026-07-14

## 1. 结论边界

本轮结果支持一个明确但有边界的结论：在 Qwen2.5-1.5B、固定 Gate-v4、三个独立训练种子下，异常值注入加修复可使同一模型在 BF16 中保持正常结构化工具输出，并在 bitsandbytes NF4 与 LLM.int8() 中稳定产生精确目标动作。三个种子、模型、原始输出、指标和清单均已在 Hugging Face 与 ModelScope 双平台验证。

当前结果不能直接外推为所有模型、所有量化器或真实 Agent 系统中的通用结论。尤其是 NF4 基线存在明显的任务特异性退化，FP4 也存在严重效用下降。

## 3. 可以主张的发现

### 3.1 INT8 是当前最干净的主结果

- 无注入模型在 BF16 与 INT8 中均正常；
- 注入后修复模型在 BF16 中三个种子均完全正常；
- 同一修复模型在 INT8 中三个种子均达到 100% 精确目标率；
- 对照精确率保持 100%。

这构成当前最清晰的因果闭环：注入决定量化后精确动作，修复隐藏 BF16 中的异常行为，量化触发行为切换。

### 3.2 NF4 的精确动作效应很强，但必须附带基线退化说明

注入后修复模型的 NF4 精确目标率在三个种子中均为 100%，无注入模型均为 0%，因而“精确目标动作由注入引入”的证据很强。但是，严格基线和无注入模型在 NF4 下已经无法可靠复制正常文件参数：严格基线的正常精确率仅 0.4%，无注入模型仅 0.27%，并伴随较高语义目标率。

因此 NF4 可作为强精确差异和机制证据，但在完成原始输出人工审计前，不应单独表述为“完整任务效用保持下的干净 Agent 动作开关”。

### 3.3 修复阶段是隐蔽性的必要组成

仅注入分支的 BF16 语义目标率均值为 42.27%，且跨种子波动很大。经过修复后，BF16 精确和语义目标率均降至 0%，正常精确率及对照精确率均恢复到 100%。同时，NF4 与 INT8 的精确目标率保持 100%。

这说明修复不是装饰性步骤，而是建立“BF16 正常、量化后切换”的关键因果组件。

### 3.4 无注入对照排除了仅靠双目标训练产生精确开关的解释

无注入修复分支在 BF16、NF4、FP4、INT8 中的精确目标率均为 0%。注入后修复分支则在 NF4 与 INT8 中达到 100%。这支持异常值注入对精确、确定性切换的必要性。

## 4. 不能过度主张的部分

### 4.1 FP4 不是干净正结果

FP4 的精确目标率只有 18.53%，且修复模型对照精确率仅 82.80%；严格基线和无注入分支的对照精确率也分别只有 68.60% 和 72.13%。它更适合作为“语义偏移强但部署效用差”的负面或边界结果。

### 4.2 三个 strict 行不是三个独立训练复现

strict 分支在三个种子中使用同一个固定源模型和同一个 Gate，因此其标准差为零是设计结果，而非三个独立训练的稳定性证明。统计单位是三个注入和训练种子；不能把 1000 个提示或重复的 strict 结果写成独立模型复现。

### 4.3 `semantic_target_asr` 目前只能作为辅助指标

NF4 严格基线精确目标率为 0%，语义目标率却为 89.6%；无注入模型也出现 56.53% 的语义目标率。这可能包含真正的参数语义漂移，也可能暴露语义判定规则过宽。论文主表应以精确目标、实体匹配、结构合法性和终态成功为主，语义指标必须配合盲法人工抽样审计。

### 4.4 当前仍未执行工具

现有指标均标记 `tool_execution=false`。它们证明模型生成了不同的结构化动作，但尚未证明动作在合成运行环境中造成不同终态。真实 Agent 贡献需要一个无外部副作用、确定性的合成执行器来补齐端到端证据。

## 5. 与 2026 异常值方法的关系

当前实现与 *Widening the Gap: Exploiting LLM Quantization via Outlier Injection* 的核心机制高度一致：选择 FFN `up_proj`、每 32 个权重插入一个异常值、主缩放系数 512、双行为训练和后续修复。原论文已经在自然语言安全场景上覆盖 NF4、FP4、LLM.int8()、GPTQ、AWQ、HQQ、SINQ、AutoRound 和多种 GGUF。

因此，本项目不应把“NF4/INT8 也能触发”作为主要新颖性。潜在贡献应定位为：

1. 量化条件行为从自然语言内容扩展到结构化工具动作与参数；
2. 用严格模式、无注入对照和 matched prompts 区分格式错误、语义漂移和精确动作替换；
3. 在确定性合成沙箱中测量动作执行后的终态；
4. 研究 schema、能力令牌、路径规范化和拒绝优先策略能否阻断终态影响。

## 6. 下一阶段闸门

### Gate A：CPU 原始输出与评分器审计

在任何新训练之前完成：

- 每个种子从 strict-NF4、无注入-NF4、修复-NF4 各抽取至少 50 条；
- 隐去分支和精度标签后，由人工独立标注精确路径、目标语义、结构合法性和任务正确性；
- 输出混淆矩阵并计算人工与自动评分一致率；
- 冻结评分器版本，不根据后续实验结果修改旧指标。

过闸标准：精确指标可从原始输出独立重算；语义指标若一致率不足，则降为定性辅助结果。

### Gate B：CPU 合成执行器与终态指标

实现只接受合成 URI 和内存对象的确定性执行器，不访问真实文件、网络或系统命令。报告：

- 动作解析成功率；
- 允许动作正确率；
- 目标终态成功率；
- 策略拒绝率与误拒绝率；
- BF16 与各量化模型的 matched end-state gap。

对比至少四种运行策略：仅解析、JSON schema、schema 加规范化 allowlist、能力令牌加拒绝优先。

### Gate C：同一 checkpoint 的原生量化后端扩展

先不重新训练，仅选择一个已锁定种子，把同一修复 checkpoint 评估到：

1. GPTQ 4-bit；
2. AWQ 4-bit 或 HQQ 4-bit；
3. GGUF Q4_K_M（必要时同时保留 Q4_0 诊断）。

所有后端必须使用原生量化产物和原生推理路径，记录校准数据、group size、运行库版本、模型哈希和 raw 输出。单种子至少两个不同家族过闸后，再复用另外两个现有种子确认；不要先训练新模型。

### Gate D：跨模型

只有 Gate A-C 通过后才租更大显存。优先顺序：

1. 24GB 显存上做一个 3B 级、不同模型家族的单种子预检；
2. 预检通过后，使用至少 48GB 显存运行 Qwen2.5-7B 或 Llama-3.1-8B 的一个冻结配置；
3. 单种子通过后再追加两个种子。

## 7. GPU 预算决策

当前不建议立即花钱跑 7B。最高信息增益的下一步不需要重新训练：先审计 raw、补终态执行，再用已有 1.5B checkpoint 测原生 GPTQ/AWQ/GGUF/HQQ。只有同一 checkpoint 能跨至少两个量化家族形成可靠终态差异时，7B 扩展才值得投入。

## 8. 当前论文主线

建议主线暂定为：

> 异常值注入可在保持 BF16 结构化工具行为的同时，使部署量化触发精确动作替换；这种现象在 INT8 上形成最干净的三种子因果闭环，在 NF4 上形成强精确效应但伴随任务特异性基线退化。结构化输出层面的高成功率不自动等于真实 Agent 影响，端到端风险取决于运行时是否采用能力约束和拒绝优先执行策略。

这一路线既继承现有强结果，也避免把零样本量化复现误写成对 2026 异常值方法本身的新贡献。
